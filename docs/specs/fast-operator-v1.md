# 快速单动作编排 v1

`jcc_fast_operator` 是一个很小的操作闸门，不是自动对局程序。它不读取平板、不排队、不重试、不判断棋子或模式，也不会自行运行任何命令。调用方必须为每次操作注入一个命令执行器，并在操作后取得更新画面。

## 设备与坐标边界

模块生成的唯一命令前缀是仓库的 `tools/adb`。该包装器从被忽略的 `设备配置.env` 读取默认设备，模块本身从不接收、记录或输出设备标识。它不会使用 Sunflower 的旧 `1024×720` 坐标，亦不会从画面推断坐标、旋转或布局。

一次 `tap` 或 `swipe` 只有在调用方同时提供以下明确证据时才会交给注入执行器：

- 同一时钟下未过期的 `live` 帧；默认最大帧龄为 750 ms；
- 场景为 `in_game`，阶段为 `preparation`；未知、战斗、大厅、回放或过期帧一律阻断；
- 已人工/实机校验的坐标标定，且其画面宽高、方向、旋转和上下文 epoch 与当前帧完全相同；
- 所有目标坐标都在该已校验画面内；动作对象的 `located_frame_id` 必须就是当前帧。

这些字段都是上游调用方的声明；`live`、`reviewed` 和读回标签都不能证明像素、阶段、帧绑定、标定或设备实际状态。画面旋转/尺寸声明的一致性检查也不是实际的截图坐标到 Android 输入坐标转换。当前首场探索期间只允许 mock/合成验证，不能把本模块接到正在执行的实战链。

## 时序与结果

同一实例以非阻塞锁保护派发：并发/重入调用返回 `busy`，模块不保留队列。同一 `action_id` 和同一源帧在调用执行器前即被一次性消费；一次触控后必须读取一个新的帧、重新定位坐标并创建新的动作。该新帧的接收时间还必须严格晚于上一次执行器返回/异常的时间；仅更换 frame ID 的旧帧及其坐标不能自动复用。这条规则针对装备栏、商店或棋盘在一次操作后改变布局的情况。

这里的“新帧”“接收时间”和 `located_frame_id` 全部是调用方标签，仍不能证明设备在动作后采集了新像素，或证明坐标确实按该像素重新定位：缓存旧图晚到、或将旧坐标重新贴到新 ID，都会越过本模块无法看到的上游边界。因此它只能强制调用方提供新的声明，不能认证重定位或画面新鲜度。

每次 `dispatch` 最多调用执行器一次，且只在持锁后以当前单调时钟核验帧龄，并在调用执行器前立即再次核验。执行器抛出任何异常（包括中断）时，操作会被记录成 `delivery_unknown` 并继续封存动作与源帧；中断仍会向外传播，调用方可用 `attempt_for` 查询保守记录，不能按原帧重试。执行器正常返回也只代表执行器已返回，不能证明 ADB 或游戏已收到触控；执行器自身的超时、中止或后台延续动作也不受本模块控制。

返回 `runner_returned` 仅表示注入执行器返回。调用方必须以**同一个 `FastOperator` 实例返回的原回执对象**调用 `record_outcome`，写成 `confirmed`、`rejected`、`unknown` 或 `withdrawn`；构造外观相同的回执或把回执交给另一实例会被拒绝。`confirmed` 必须引用不同于源帧、且时间严格晚于执行器返回的读回帧；不能用于未发送或 `delivery_unknown` 的操作。通过这些检查也只表示本实例观察到执行器返回，读回画面和真实触控仍是调用方声明。

上述锁和消费记录只覆盖**同一 Python 实例**，不构成持久化或跨进程的唯一写者锁。此仓库当前没有可信的跨会话设备租约，因此此模块只是一份模拟单实例原型，不具备实机生产接入资格；任何未来实机集成必须在它之外取得并持续验证唯一写者租约，再另行实测/审核，不能仅靠本模块的 `source_kind`、时钟或 `reviewed` 声明。

记录的发送耗时只覆盖调用执行器的本机时间；不包含取帧、识别、思考、ADB 传输、游戏渲染、物理屏幕可见性或人眼反应。它不是实战反应速度、识别准确率、自动操作可靠性或上分成绩。

## 当前验证

专属单元测试只使用合成帧和注入的 mock 执行器，覆盖新鲜度、场景/阶段、来源、几何/旋转、坐标边界、单次派发、失败、读回因果、滑动和重入。没有连接平板、读取账户或游戏画面。
