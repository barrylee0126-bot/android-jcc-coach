# 探索局条件建议 v1

状态：独立、纯输入的探索局条件模块。日期：2026-11-03。

代码入口：[src/jcc_exploration_conditions](../../src/jcc_exploration_conditions/)。它把已有研究里的少量通用前提转成可测试的条件检查：预算下的购买、出售后的合法棋盘、可上场空位、装备的散件/配方/携带者条件。它不读取平板、不会调用 ADB、不会读取屏幕、没有模型调用，也不会输出点击、拖拽或自动操作。

## 输入和证据边界

`assess_conditions(request)` 只接收调用方完整提供的字段。每个字段都必须使用 `known`、`unknown`、`ambiguous`、`stale` 或 `not_applicable`，而非 `known` 时值必须为 `null`。对**调用方已声明**为旧帧、冲突或不可读的字段，组件不会借由残留数字生成结论。

组件不校验帧绑定、新鲜度、跨帧混用、来源真实性或调用方是否把错误的内容声明为 `known`；这些仍是上游识别、状态组装和动作后回读的责任。

调用方可声明 `synthetic`、`manual_hypothesis`、`replay_candidate` 或 `live_candidate`。后两者依旧只是机器候选；所有输出固定为：

```text
execution_eligible=false
strategy_recommendation=false
automatic_action=null
```

因此它可供首场探索的观察与复盘使用，但不能直接接到实时点击。它不绑定当前国服模式、赛季、补丁、商店/利息规则、棋子或装备效果；`live_candidate` 不提升为人工真值或实战策略。

## 四类条件

| 条件 | 必要输入 | 成立时仅表示 | 阻断或保留 |
| --- | --- | --- | --- |
| 购买 | 金币、调用方保留线、下一次购买预留、候选价格、立即改善、备战席位置、准备阶段 | 可把购买列为候选 | 任一字段未知；不在准备阶段；不能立即改善；余额低于显式预算。 |
| 出售 | 售价、对象非关键、出售后棋盘合法、准备阶段 | 可把出售列为候选 | 不猜售价、不指定出售对象；关键或合法性不明即保留。 |
| 上阵 | 合法空位、候选可上场、准备阶段 | 可把上阵列为候选 | 不推断棋子强度、羁绊或站位坐标。 |
| 装备 | 闲置散件、配方、散件确实匹配配方、携带者、装备槽、携带者适配该配方、携带者职责、准备阶段 | 可把装备列为候选 | 不比较装备强度、不推断当前配方、不执行拖拽。 |

购买检查只验证调用方设定的算式 `gold - candidate_price >= reserve_gold + next_purchase_reserve`。其中保留线、价格和预留都是输入，**不是**本项目确认的利息、商店或最佳经济规则。

## 来源对应

本模块使用以下资料来定义需要哪些输入及何时保留未知，不把其中版本未闭合的英雄、价格或装备结论写进代码：

- [来源驱动的玩法条件卡](../../资料/调研/07_来源驱动的玩法条件卡_20261102.md)卡 03：刷新和购买共享同一预算，关键价格、空位、阶段与目标不清则不能给精确刷新/购买结论。
- 同一文件卡 04：散件、配方、携带者、槽位和职责均需确认；来源版本不闭合时只列候选。
- 同一文件卡 07：实际报价、搜牌、升级和购买共享预算，旧报价/旧阶段必须撤销。
- [装备、强化与站位研究](../../资料/调研/03_装备强化与站位.md)：装备效果、配方、携带者和动作合法性应分开观察。

这些是来源支持的工程条件，非当前国服规则认证或实战收益证明。

## 运行与验证

```sh
PYTHONPATH=src .venv/bin/python -B -m unittest discover -s src/jcc_exploration_conditions/tests -v
```

测试仅使用 `synthetic_snapshot()` 的虚构字段。它检查预算正反例、未知和过期字段阻断、出售/上阵/装备的共同条件、实时机器候选不升级为可执行动作、严格字段结构及输入/输出隔离。通过不代表画面识别正确、当前国服规则成立、Agent 能完成对局或能上分。
