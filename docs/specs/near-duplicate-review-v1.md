# near-duplicate-review-v1：离线近似画面候选与人工分集复核

开发 11E，2026-11-02。可选入口：[`src/jcc_samples/near_duplicates.py`](../../src/jcc_samples/near_duplicates.py)。依赖现有 Python、Pillow、NumPy、jsonschema；不增加依赖、不改动样本工作流或测评器。

**输出只是一份私有、待人工检查的候选清单。方法及阈值只经过合成工具测试，未用真实游戏样本校准。画面接近不证明局面相同；没有候选也不证明样本独立、没有泄漏、答案正确或 M1 通过。** 本模块不删除或改写样本、不合并或拆分分组、不挑代表帧、不分配集合、不产生验收有效样本数。

## 1. 输入边界与运行

沿用 [sample-workflow-v1](sample-workflow-v1.md) 的私有工作区、完整标注契约、资产映射和单帧 PNG/JPEG 校验。每个输入必须明确指定工作区及其 `manifests/` 内的**完整当前冻结导出**，清单内容及数组顺序必须与当前工作区标注一致。过时导出、子集、重排清单、缺失或被替换的资产均停止，不跳过失败条目。

可同时检查 1–8 个明确指定的工作区，以发现不同采集批次之间的线索。不会扫描磁盘寻找其他工作区。必须由总控提供所需开发、验收、隔离来源；遗漏一个工作区或一条来源，本工具无法知道。每个工作区内部仍须通过原契约，不会为了出候选而放行已知分集违规。

已有导出若过时，应由原工作流明确导出新的完整修订；工具本身不更新或修复输入。要审查旧冻结版本，应使用其完整且一致的私有工作区快照，不能拿旧清单配当前映射或当前分集。

在项目根目录运行，以下目录均为占位符，不能指向源码、Git 检出或云同步目录：

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m src.jcc_samples.near_duplicates --help

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m src.jcc_samples.near_duplicates \
  --source /absolute/local/private/source-a manifests/frozen.json \
  --source /absolute/local/private/source-b manifests/frozen.json \
  --output-dir /absolute/local/private/reports \
  --output-name near-review-v1.json
```

报告目录必须已经存在、归当前用户所有、无组或其他用户访问权限，且位于全部输入工作区之外；通常使用 `0700`。报告文件以 `0600` 排他创建，不覆盖旧报告，不自动创建目录。只持有既有工作区锁并读取内容，不创建锁、不改修订、不写样本或清单。扫描期间会阻止遵守同一锁的采集/编辑进程，应安排在来源导出后、采集暂停时运行。

命令行成功只打印状态和数量，不打印图片、标签、OCR、参数值、路径、来源身份或原始场次代号。报告也不含这些内容，但包含可关联的来源摘要、集合和候选关系，**仍须只留本机私有目录，不作为可公开附件**。本模块不联网、不调用外部进程、OCR、模型、平板或采集程序。

Python 接口独立导入，不改变原包的公共导出：

```python
from src.jcc_samples.near_duplicates import (
    FrozenSource, ReviewConfig, NearDuplicateError, review_frozen_sources,
)

report = review_frozen_sources(
    [FrozenSource("/absolute/local/private/source-a", "manifests/frozen.json")],
    config=ReviewConfig(),
)
```

Python 接口只返回完整候选报告或抛出 `NearDuplicateError`（含稳定 `code`、不含输入内容的说明），不写文件。调用方负责私有保存；不要打印完整输入对象或异常链。接口接受明确的 `list/tuple` 来源，不自动推断默认目录。

## 2. 方法、分数和未校准阈值

版本：`jcc-near-duplicate-review-v1.0.0`。这是轻量工程候选器，不是语义识别器或重复概率模型。

每张已经过原工作流完整校验的图像再次读取并对照字节 SHA-256。仅在内存中生成：

- Pillow LANCZOS 缩放的 `32×32` RGB 缩略特征，采用原编码 RGB 数值，不做 ICC、HDR 或感知颜色校准。
- 灰度缩至 `9×8` 后，以每行相邻像素的 `right > left` 得到 64 位差分哈希。
- `32×32` RGB 划成 `4×4` 个 `8×8` 分块，分别计算平均绝对差。

对所有无序图像对先检查宽高比，再比较粗粒度特征。缩放仅用于特征，绝不重写原图。

| 参数 | 默认值 | 含义与接受范围 |
| --- | ---: | --- |
| `aspect_tolerance` | 0.02 | `abs(w1*h2-w2*h1)/max(w1*h2,w2*h1)`；允许 `[0,0.1]`。超出只记几何跳过，不称为独立。 |
| `global_mae` | 20 | 整张 RGB 缩略图平均绝对差，单位 0–255，阈值允许 `[0,255]`。 |
| `dhash_hamming` | 12 | 64 位差分哈希的不同位数，允许整数 `[0,64]`。 |
| `tile_mae` | 10 | 分块平均 RGB 绝对差，阈值允许 `[0,255]`。 |
| `min_matching_tiles` | 12 | 16 块中误差不超过 `tile_mae` 的最低数量，允许整数 `[1,16]`。 |
| `local_global_mae` | 45 | 局部容忍路径仍要求整图误差不超过该值，允许 `[0,255]`。 |

满足以下任一条件即列为待审候选：字节相同；解码像素相同；整图误差及哈希距离均在阈值内；或足够多分块相近且整图误差在局部路径上限内。相同字节/像素在同一工作区已会被原校验拒绝，新模块可提示不同工作区之间的完全重复。报告保留全部命中的原因，不把分数转换成置信度。

灰度缩略图标准差小于 4 时附 `low_information_warning`，提醒平坦图、遮罩和低纹理的碰撞风险。这个标记同样未经真实校准，不会过滤或接纳样本。

有损重编码、同宽高比的轻微缩放、部分画面的局部变化已由合成案例验证可产生候选，未保证覆盖其所有形式。共同 UI、相同色块、动画背景可能误报；裁剪、位移、旋转、遮罩、重排、大幅亮度变化或重度压缩可能漏报。金币数字、棋子、商店等小区域的关键改变可能被缩略特征淹没。不能用“分数低”认定语义相同，也不能把“分数高”当作独立性证明。

## 3. 保留分组、跨集合提示与人工复核

报告中的 `entries` 仅包含：本次运行生成的 `entry-000001`、`source-0001`、该来源冻结清单中从 1 开始的顺序号、原声明集合与样本类型，以及按来源区分的场次/去重组/局面组匿名别名。代号不是新分组，不会回写输入。原始代号和人员身份不会被复制到报告。

`candidates` 逐对记录原因、分数、原边界关系和 `pending/null` 复核状态。优先顺序为 `development↔acceptance`、其他跨集合、同集合；不截断优先列表、不通过传递关系合并候选。如果 A 接近 B、B 接近 C，工具不会自动宣称 A 与 C 同组。

跨工作区的场次/去重组/局面组使用独立匿名空间；原始代号恰好相等只报告 `declared_code_equal`。不同来源可能复用普通代号，也可能把同一原场次改名，因此等号与不等号均不认证真实身份。跨来源且跨集合的场次或去重组代号相等时，即使画面不近似，仍单独生成 `declared_boundary_alerts`，提示总控辨别“同源”还是“代号碰撞”。局面组代号不单独触发来源泄漏判定。

人工使用顺序：

1. 在私有运行记录中保存本次来源参数顺序、方法/配置及报告摘要。按照 `source` 与 `manifest_ordinal_1based` 在**哈希一致的完整冻结清单**中定位原条目；来源位置只记录在原有私有交接中，不填进公开文件。
2. 先处理开发与验收间的视觉候选及代号重叠，利用原采集场次、时间线和分组证据判断是否同源，再私下检查原画面。近似外观与“相同局面状态”必须分别裁决；不因工具给出一个候选就减少或合并局面数。
3. 用独立私有复核记录保存报告/来源摘要、候选序号、复核人员和依据、已解决或待核状态。不要把报告的 `pending` 改名为已通过，来代替实际画面与来源检查；工具不自动写人审结论。
4. 如需纠正来源分组、代表帧或集合，按原样本流程另行明确处理、独立复核并重新冻结。对新冻结来源重新运行候选检查；旧报告不能沿用为新修订的已审证据。

这份报告不能直接作为 evaluator 的样本输入，也不能填补其真实场次/代表图/不同局面缺口。`dedupe_revision` 应关联实际冻结分组及人审依据，单独填一个算法版本不构成去重完成证据。多个工作区的检查结果也不能绕过 [evaluation-v1](evaluation-v1.md) 的单一冻结数据集要求。

## 4. 可复现性与覆盖状态

同一运行环境、相同来源内容及顺序、相同配置会生成相同报告。报告不带当前时间或随机生成的来源身份；条目顺序由输入来源顺序及原清单顺序确定。

记录方法版本、完整配置、Python/Pillow/NumPy/jsonschema 版本、本模块/原样本工作流/契约校验模块/Schema 的 SHA-256、每个完整 workspace 和 manifest 原始字节摘要、manifest 的 canonical 摘要，以及按条目顺序绑定的图像字节/像素摘要的整体 SHA-256。canonical 使用排序对象键、UTF-8、紧凑分隔，保留数组顺序；`1` 与 `1.0` 不等同于同一个冻结导出。摘要只能绑定内容，不能证明来源、人员独立或权利状态。

`complete_candidate_scan` 仅表示明确提供的全部输入通过检查，所有图像对都经过几何过滤，满足几何条件的图像对都完成特征比较。报告同时给总对数、真正评分数及宽高比跳过数；不会把未比较对冒充已判不重复。缺少其他工作区仍无法发现，故 `caller_scope_completeness=not_verified`。

`manual_review_status` 固定为 `pending`，即使候选数为零也一样。`effective_acceptance_samples`、`independent_recordings`、`distinct_game_states`、`accuracy` 固定为 `null`，`full_m1_acceptance=not_assessed`。输入条数、来源数和候选对数只是工具覆盖计数，不是独立样本量或真实准确率。

## 5. 失败、隐私和资源边界

复用原工作区对项目/Git/已知同步路径、符号链接、权限、硬链接、大小、编码格式、完整解码、EXIF 方向、哈希和分集的检查。沿用每文件 32 MiB、每图 1600 万像素上限；额外拒绝非完全不透明图像，不猜测背景；解码或校验警告转为固定错误，避免元数据警告外泄。不会自动脱敏、剥除 EXIF、旋转或修复图像。任意自定义同步/备份位置不能靠路径识别完全发现，仍须使用确知的本机私有目录。

| 错误码 | 意义 |
| --- | --- |
| `manifest_snapshot_mismatch` | 不是完整当前冻结清单，或顺序/内容已变化。 |
| 原工作流错误码，例如 `split_isolation`、`asset_integrity`、`unsafe_permissions` | 原始边界失败；不会降级继续。错误文字已固定化，不回显来源内容。 |
| `repeated_source` / `empty_corpus` / `invalid_sources` | 来源重复、全部为空或未明确指定可接受来源。 |
| `scan_limit_exceeded` / `candidate_limit_exceeded` | 资源预算不足；整体失败，没有截断、只审前几项或部分完成报告。 |
| `input_changed` | 再读取或最终复查时发现资产/清单/工作区字节发生变化。 |
| `unsupported_transparency` / `decoder_warning` | 透明度或解码警告需调用方明确处理，工具不猜测。 |
| `source_write_forbidden` / `output_exists` | 报告试图进入来源工作区，或目标已存在/被并发占用；不覆盖。 |
| `invalid_config` / `invalid_snapshot` / `local_resource_failed` / `local_io_failed` | 非法配置/结构或本地资源失败，不输出部分结论。 |

默认最多 400 条输入、80,000 个图像对、10,000 个视觉候选及 10,000 个代号边界提示；硬上限分别为 2,000、2,000,000、100,000。所有来源合并后统一计数。不要通过拆成互不比较的小批次来声称完整分集核查；需要扩大预算时须保留明确配置并重新运行完整范围。

报告先写入私有匿名暂存文件并同步，再用同目录排他硬链接发布完整 JSON。普通写入/链接异常清理本次暂存文件，不删除同名旧报告；不支持硬链接的文件系统会失败而非降低保证。进程被强杀可能留下 `.near-review-*.tmp` 或已完整发布但未收到成功返回的报告，工具不自动接管或删除恢复材料。不要从暂存文件或仅有文件存在推断运行成功；需核对返回状态、完整 JSON、方法与来源摘要。本版不承诺断电目录持久性，也不防御同用户恶意并发替换整个父目录的全部竞态。

输入锁是合作式锁；扫描末尾还逐一复核来源字节，以发现忽略锁的普通写入。之后发生的新修改会使报告失去当前适用性。预期错误 CLI 返回 2，stderr 为固定 `status=no_report` 对象，stdout 不产生候选摘要；成功返回 0 仍只是候选扫描完成。

复杂度为每张图一次原校验及特征提取，加 `O(N² × 32 × 32 × 3)` 的全配对比较；保留 `O(N × 32 × 32 × 3)` 特征及有预算的报告条目，不保留全部原图。大分辨率解码、完整 JSON 校验、来源数量和候选密度都会增加耗时和内存，不能用桌面合成测试预测平板实时响应。
