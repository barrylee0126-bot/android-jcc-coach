# 合成买卖对照与本机模型 v1

这是离线、仅限虚构输入的最小决策演示，固定 CLI 只构造虚构文字，不读取游戏画面、真实回放或实时局面，也不输出正式策略、操作或自动购买。可导入接口只能检查调用方声明的 `synthetic` 标签，无法自行证明输入确属虚构；调用方不得将真实局面标成虚构数据传入。真实模式、版本、棋子身份与归属、实际买卖价格及适用策略来源均标为 `unknown`。演示中的保底目标、价格与持有数只是显式假设，不是当前国服规则或上分策略。

## 可运行示例

前提：Python 3.11、项目现有 `jcc_economy_lab`，以及运行在本机 `127.0.0.1:11434`、已安装 `qwen3-vl:4b-instruct` 的 Ollama。演示不会下载模型、读取设备或查找截图：

```sh
PYTHONPATH=src .venv/bin/python -B -m jcc_decision_bridge --demo --runs 2
```

示例假设有 31 金、持有 2 张“虚构棋子甲”；买入价假设为 2 金，卖出回收假设为 1 金。给定的虚构目标是买卖后至少保留 30 金，并在满足保底的选项中尽量多保留该棋子。

| 单独选项 | 假设余额 | 假设持有数 | 在该虚构目标下 |
| --- | ---: | ---: | --- |
| 买一张 | 29 | 3 | 低于 30 金保底 |
| 保留 | 31 | 2 | 满足保底，持有数较多 |
| 卖一张 | 32 | 1 | 满足保底，持有数较少 |

程序用 `jcc_economy_lab.analyze_purchases(..., rule=None)` 计算买入后的现金；卖出与持有的加减法直接由本模块按输入假设计算。所有选项的结果都显示在 `program.options`，但只有满足虚构约束的选项会送给模型；程序预先计算的优胜选项不放进模型提示。模型返回受限的选项 ID 和理由代码，程序核对它与已算出的虚构目标是否一致。中文解释由程序依据核对后的选项生成，**不是模型自由生成的事实说明**。

模型不可用、格式错误、返回未知或与程序事实冲突时，不生成已验证的模型解释；程序已计算的虚构事实仍可查看。缺少输入、价格、持有数或虚构目标来源时保持未知；非 `synthetic` 输入直接阻断且不调用模型。无论结果如何，`formal_strategy_recommendation=null`、`action=null`、`execution_eligible=false`。金币利息固定未知，不自动套用历史利息或版本数据。

`program_seconds` 是单次内存计算；模型的 `wall_seconds` 包含本机 API 请求及响应，另记录本机服务报告的模型加载、提示处理及生成时间。进程总时间还包括模型清单查询等开销。次数很少的冷、热实验不是稳定性能分布，也不含画面采集、视觉识别、真实策略、显示或操作，不能作为实战延迟或胜率。

## 复用与取舍

- [金币条件分析](economy-lab-v1.md)承担已知假设下的买入现金比较，并保留无规则时的利息未知；本模块没有改动它。
- 仓库既有 `tools/jcc-decision-demo` 通过本机 Ollama 调用 [jcc-replay-analyst](https://github.com/HuanNan520/jcc-replay-analyst) 的 `DecisionLLM`；上游提示词绑定旧 S17，不能当成本局规则。本示例沿用本机模型方向，但没有复用或改写这套旧赛季提示词。该上游的固定版本与许可见项目 `THIRD_PARTY_NOTICES.md`。
- [Sunflower](https://github.com/Carey8175/Sunflower) 是项目早期视觉接口引用，本演示不调用它；两个上游引用继续保留在项目主说明与第三方声明。
- 本地模型必须先出现在本机 Ollama 的 `/api/tags`；网络请求只允许固定的本机回环 `/api/tags` 和 `/api/chat`，并禁用代理。这里发送的只有此合成例子的文字，没有图像、账号或真实棋子信息。

运行测试：

```sh
PYTHONPATH=src .venv/bin/python -B -m unittest discover -s src/jcc_decision_bridge/tests -v
```

合成测试核对三个选项、缺失/非合成输入阻断、模型未知/冲突及本机接口边界。它们不能证明模型有真实游戏常识，或证明当前国服买卖建议正确。
