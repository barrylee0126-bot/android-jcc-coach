# 短提示计时原型 v1（14B）

日期：2026-11-02。独立于 14A 的本机原型；所有卡片始终写明 **“模拟计时”** 和 **“虚构测试提示 · 不代表游戏建议”**。它测显示事件通路，不判断游戏局面，也不输出买卖、阵容或装备建议。

## 运行与交付

在项目根目录运行：

```sh
PYTHONPATH=src .venv/bin/python -B -m jcc_timed_overlay
```

打开终端输出的本机地址。默认自动选择空闲端口；`?compact=1` 为紧凑页，`--open` 可自动打开浏览器。`Ctrl+C` 停止。程序只有 Python 标准库及随附网页文件，不安装依赖、不启动设备工具、不连接模型，也没有后台自启。

也可使用系统 Python 直接运行：

```sh
PYTHONPATH=src python3 -B -m jcc_timed_overlay --port 0
```

页面提供一次完整试播和单项测试。完整试播含 5 个合成样本：三次可显示提示、一次无结果、一次等待超时，另有过期、主动撤回和停止心跳。不是循环；没有浏览器回报时，可显示样本也会记为显示超时。内置源真实记录本进程的调度时间，但有意等待约 80ms 才签发结果，这个数值没有游戏含义。

默认日志是权限为 `0700` 的临时目录内的 `events.jsonl`，文件权限为 `0600`；终端显示位置，停止后保留。可用 `--log /absolute/path/new-run.jsonl` 指定尚不存在的新文件，拒绝覆盖已有日志。运行时日志不要写进公开源码。程序只绑定 `127.0.0.1`，没有外网监听选项、文件浏览、上传、任意文字或图像入口。

主要参数：

| 参数 | 作用 |
| --- | --- |
| `--port 0` | 默认自动选本机空闲端口 |
| `--input PATH` | 跟随一个本机匿名 JSONL 文件的新增完整行 |
| `--clock-domain-id ID --stream-id ID --source-kind KIND` | JSONL 模式三个必需来源声明 |
| `--source-timeout-ms 1500` | 按生产方签发时间计算的源静默阈值，范围 250–10000ms |
| `--paint-timeout-ms 1200` | 从收到 ready 到等待绘制机会回报的期限，范围 100–10000ms |
| `--log PATH` | 新建匿名生命周期日志 |

## JSONL 联调合同

这是一份供总控与 10H 评审的独立候选接口，未修改共享 Schema 或正式策略接受门槛。真实源名称只分类计时元数据，页面文案始终是固定的“模拟计时 · 仅测试显示”。不得把实际建议改标签后塞入本接口。

每行严格接受下列 10 个键，不接受额外字段、重复键、非有限数字、控制图像或任意提示文本：

```json
{
  "schema_version": "timed-overlay-event-v1",
  "sample_id": "anonymous-sample-0001",
  "source_kind": "synthetic",
  "stream_id": "anonymous-stream-1",
  "sequence": 1,
  "clock_domain_id": "declared-host-clock-1",
  "frame_received_monotonic_ns": 10000000000,
  "emitted_monotonic_ns": 10080000000,
  "expires_at_monotonic_ns": 12000000000,
  "status": "ready"
}
```

以上数字仅说明结构，**不能直接重放**。运行时须填写当前时钟域中的时间；旧时间会被拒绝。字段含义：

| 字段 | 约束和含义 |
| --- | --- |
| `sample_id` | 匿名机会标识；同一样本的 pending 和结果使用同一 ID，整个服务会话不可复用 |
| `source_kind` | `synthetic / replay / device_readonly`；必须与启动声明一致，不改变模拟提示标识 |
| `stream_id` | 匿名生产流，禁止使用设备标识；流改变须新建服务会话 |
| `sequence` | 整个流的事件序号，包括心跳和控制事件；首个事件可为任意正整数，此后必须逐个加 1，缺号会关闭本服务会话的输入；不以 ID 去重来源数据 |
| `clock_domain_id` | 与启动声明一致的匿名时钟域标签；标签匹配不构成同域证明 |
| `frame_received_monotonic_ns` | 当前 Mac 进程收到完整帧之后的 `time.monotonic_ns()`，不能替代设备物理显示时间 |
| `emitted_monotonic_ns` | 生产方签发本行的 Mac 单调时间；不是浏览器时间 |
| `expires_at_monotonic_ns` | 固定失效点，第一次 pending 即确定，ready 不得延长 |
| `status` | 样本事件或控制事件，见下表 |

三个 ID 均只接受 1–80 个 ASCII 字符：首字母或数字，后续可含数字、字母、点、冒号、短横线和下划线。时间和序号只接受 64 位有符号范围内的正整数，拒绝布尔值；所有状态均须满足 `服务启动时间 ≤ frame ≤ emitted ≤ 当前时间` 及 `0 < expires - frame ≤ 30 秒`。除 `timeout` 外，所有状态还须满足 `emitted < expires`；`timeout` 是不显示内容的终态记账，允许在截止前、恰好截止时或截止后签发，详见下文。签发时间距当前时间达到源静默阈值即拒绝，不以读取旧行来续源租期。建立新样本的帧时间必须严格前进。

| `status` | 行为 |
| --- | --- |
| `pending` | 开始一个机会，立即撤下旧样本，等待结果；到截止仍无结果记 `result_timeout` |
| `ready` | 独立开始新机会，或完成当前 pending；显示固定测试文案，等待绘制机会回报 |
| `no_result` | 本机会无结果，撤下旧提示，记 `no_result` |
| `timeout` | 输入方明确报告本机会超时；可在原截止时或之后签发，也保留提前报告处理超时的能力；新机会记 `result_timeout`，已终结机会仅留历史，不显示或重复计数 |
| `unknown` | 结果未知，不显示提示，记 `unknown` |
| `heartbeat` | 更新源存活，不增加机会、不改提示修订、不延长提示截止点 |
| `invalidated` | 源宣布当前上下文失效，撤下提示，并将来源帧水位至少推进到本事件的 `frame_received_monotonic_ns`（包含该帧）；不增加机会 |
| `disconnected` | 明确断开，撤下提示，并建立与 `invalidated` 相同的包含式帧水位；不增加机会 |

控制事件也保留完整 10 字段结构；可用 `sample_id="source-control"`，签发时间为当前时间及一个未来截止点。`invalidated/disconnected` 的帧时间声明本次失效覆盖到哪一来源帧，水位取它与此前已接受样本帧时间的较大者，不能后退；即使该帧尚未发送过 pending，也不能在之后靠新事件序号或新 ID 显示该帧及更早帧。恢复须有严格更新的帧和新样本 ID。`heartbeat` 不推进帧水位，不会妨碍当前 pending 正常完成；控制事件的时间窗也不延长提示固定期限。建议至少每 300ms 写一次心跳；所有写入者须只有一个、按同一序号流串行写完整行。先发 pending 再执行识别，才能记录识别无输出的分母。仅发送成功 ready 的生产者会漏掉上游无输出，14B 无法凭空恢复这些机会。

新帧 B 到达时，直接发 B 的 pending 已会撤下 A 的提示。如果桥接先单独宣布 A 失效，再发 B 的 pending，失效水位应明确覆盖 A；若将失效控制事件的帧时间写成 B，则 B 本身也已失效，随后 B 的 pending/ready 都必须拒绝。这是 15A 联调必须按最终合同复测的边界。

首个正整数序号用于兼容跳过历史字节后的附着；它不是已读取历史事件的证明。接受首个事件后，`1 → 3` 等任何缺口都可能漏掉失效通知，所以当前提示立即撤回，本服务会话不再接受后续源事件；后续心跳、新帧、补回缺号或更大的序号均不能恢复。必须重启服务建立新会话；本协议没有通过普通事件证明恢复水位的机制。

同一样本的 pending → ready/no_result/timeout/unknown 必须保持原帧时间和原截止点，签发时间不得倒退。样本已到期、撤回、完成、被新样本替代或断开之后，任何晚到结果都不能复活它。迟到的 pending/ready、重复或倒退序号、缺号、错误来源和错误时间绑定仍按拒绝屏障处理；合法终态的历史确认遵循下述例外。需要重试须由上游明确产生新机会、新帧和新 ID，不能靠改 ID 给旧结果续期。

### 超时与终态记账（14D）

`timeout` 的时间例外只取消它的 `emitted < expires` 要求，不放宽正整数、正且不超过 30 秒的原有效期、同源同钟、服务启动边界、未来时间、签发新鲜度或连续序号检查。`expires` 仍是原来的固定点，不能为发送 timeout 改成未来时间；提前 timeout 表示生产者已耗尽自己的处理预算，不要求必须先经过显示截止点。`expired` 只可能出现在视图中，不是合法输入事件状态。非 timeout 事件若在 `expires` 或之后签发仍被拒绝；已在有效期内签发但读取时才到期的样本，也沿用原有“记为结果超时、绝不显示”的处理。

合法 timeout 与其他事件共享同一个序号流：例如 `pending(seq 1) → timeout(seq 2) → 新帧 ready(seq 3)` 可连续接收，不会因 timeout 的原期限已到而丢掉 seq 2。首次可从任意正整数附着；终态的重复确认必须使用下一个序号，不能重放原序号。重放、倒退或真正缺号并未获得豁免，缺号仍关闭本服务会话。

| 消费时的情况 | 合法终态事件的处理 |
| --- | --- |
| 当前 pending 仍在等待结果 | 第一次 timeout 将机会终结为 `result_timeout` 并撤下当前机会；不要求再等到原显示截止点 |
| pending 已被 tick 自动判为结果超时 | 匹配原 ID、帧和截止点的 timeout 接受为历史确认；不再增加机会、不再写一次 sample_outcome、不改原到期原因与时间 |
| 同 ID 已产生 ready、已有最终结果或已退休，包括被新样本替代、失效和断开 | 合法 `timeout / no_result / unknown` 仅写历史 source_event，返回接受；不覆盖首次结果及其时延、撤回原因，不改当前样本、提示修订、render token 或固定失效点；历史签发时间仍须不倒退 |
| 没有同 ID 记录，帧严格更新 | timeout 本身可建立一个机会，且只计一次 `result_timeout`；若原期限已到，视图可保持 `expired`，不会显示内容；作为新帧仍会撤下更旧的提示 |
| 没有同 ID 记录，帧在包含式失效水位或更早 | 不建立机会，拒绝并单列计数；已通过完整结构、来源、序号及时间检查的 `timeout / no_result / unknown` 属于不可显示的旧终态，此次拒绝不撤掉更新提示，也不后退水位或关闭序号流 |

最后一行不是旧帧复活路径：换 ID 仍不能使旧帧增加机会或获得显示资格。它只避免不可显示的旧终态清空更新画面。终态也必须先通过一般检查；非法时间、重复序号、缺号、日志故障或会话限额仍可触发屏障。源存活仍按签发时间维护，不延长任何样本的固定期限。一次机会可能接收多条终态历史确认，但机会数和最终结果均只计一次；已先记为来源静默、替代等结果时，晚到 timeout 也不会将其改写成 result_timeout。

日志中的历史确认仍使用 `source_event`，附 `historical_only=true`；拒绝记录增加 `withdrawal_required`，指出本次拒绝是否要求撤回。报告的样本字段、HTTP 路由及 Schema 版本不变，原结果的签发时间和时延不会被历史确认改写；最新历史签发时间单独在会话内维护。计数应依据 `opportunities / outcomes`，不能把每条 source_event 都当作一个新机会。

### JSONL 读取边界

读取器启动时跳过文件已有全部字节，并检查跳过位置前一字节是否为 LF 换行。如果旧文件以未结束的部分行结尾，继续丢弃后续字节直到下一个 LF（含该 LF）；即使追加后缀本身恰好是合法 JSON，也不能将它当独立记录。只消费该边界之后追加并带换行的新行。空行、坏 JSON、超长行（4096 字节以上）和额外字段会撤回旧提示并记录固定拒绝原因，不回显原始行。文件删除、替换或观察到截短后终止该输入源，包括等待旧部分行边界期间，须重启会话；不自动重放新文件。只读普通文件，拒绝软链接、目录和 FIFO。文件检查不是防篡改证明，仍要求单一可信本机生产者。

### 脱离 10H 验证 JSONL

在项目根目录，终端 A 创建本次运行的空文件并启动读取：

```sh
event_dir=$(mktemp -d -t jcc-timed-fixture)
touch "$event_dir/events.jsonl"
chmod 600 "$event_dir/events.jsonl"
printf '%s\n' "$event_dir/events.jsonl"
PYTHONPATH=src .venv/bin/python -B -m jcc_timed_overlay --input "$event_dir/events.jsonl" \
  --clock-domain-id demo-clock --stream-id demo-stream --source-kind synthetic
```

打开输出的页面。终端 B 将上面打印的实际路径代入 `--output`，运行一次独立的合成生产者：

```sh
PYTHONPATH=src python3 -B -m jcc_timed_overlay.synthetic_jsonl \
  --output /absolute/path/to/events.jsonl \
  --clock-domain-id demo-clock --stream-id demo-stream
```

该生产者只接受已存在的空普通文件，约两秒写完 3 个合成机会：显示、无结果、等待超时，然后明确断开。再次运行需要新的空文件及新的服务会话，避免序号和样本复用。JSONL 模式隐藏并禁用内置演示按钮，避免两个生产源混写。

## 显示、撤回与时钟边界

服务端每约 25ms 维护一次生命周期，也在读取和接收事件时复核。网页约 150ms 拉取状态，50ms 检查倒计时；读取请求 800ms 超时，单次展示租期最多 1000ms。浏览器用请求开始点扣除整个请求耗时，保守换算剩余预算；同修订后续响应只更新源租期，不延长原失效点。

服务端到期、等待绘制回报超时、源静默、断开、输入错误、时钟异常和新样本均建立撤回屏障。浏览器断网、租期用尽、页面转后台、页面隐藏/恢复也清空旧内容并封存原修订。重新连接或收到同修订不会复活旧提示；新修订才可能显示。

`visibilitychange`、`pagehide` 和 `pageshow` 均取消在途状态请求并推进请求 epoch；旧请求即使在取消后才完成响应体或抛出错误，也不能修改新状态、切换会话或撤下新提示。`pagehide` 后暂停状态轮询；`pageshow` 重新请求当前状态，从隐藏状态或往返缓存恢复时也封存旧修订。首次正常加载的 `pageshow` 只更新请求 epoch，不会把刚刚显示的首个修订误判为恢复前的旧内容。新请求仍须通过原有修订、租期和截止点校验。

**服务端时钟域：** 内置合成源与存储器同进程，报告标记 `in_process_synthetic`。外部 JSONL 的任何来源，包括 `synthetic`，均标记 `producer_declared_same_host_unverified`。启动参数或复制标签不验证时钟。10H 联调必须核实生产者和服务运行在同一 Mac、同次开机、同一 `time.monotonic_ns()` 基础上；禁止把设备时钟、UTC、浏览器 `performance.now()` 或另一台主机的数值直接比较。历史回放应使用本次回放的主机接收与签发时间，保留 `replay` 分类；原始录制时间不能据此当作本次延迟起点。

**浏览器时钟域：** `performance.now()` 只用于浏览器内部耗时；同时观察 `Date.now()` 的经过量，取较大者保守扣期，发现倒退则撤回。纳秒时间在报告中转为十进制字符串，网页不对超过安全整数范围的纳秒值直接运算。

**绘制机会回报：** 页面记录 DOM 更新，然后在两次 `requestAnimationFrame` 回调后复核仍是当前样本、仍有效、页面可见且卡片与视口相交，再回报 `paint_opportunity`。报告是页面自己的观测，不是像素输出、系统合成器、显示器刷新或用户视线的独立证明；页面可见也不能排除被其他窗口遮挡。回报可伪造，没有生产安全认证含义。

浏览器主线程阻塞、系统休眠或进程暂停时，定时器无法保证在物理截止点改写屏幕；恢复执行后会重新撤回。页面关闭前的撤回回报是尽力发送，可能丢失；服务端样本超时和结束状态仍会记录。此原型不提供硬实时保障、系统置顶或鼠标穿透。

## 记录口径

`GET /api/view` 返回当前展示状态；`GET /api/report` 返回全会话报告；`POST /api/browser-event` 只接受固定枚举、匿名标识与浏览器时间字段。浏览器回报绑定会话、样本、修订和随机 render token；旧回报可作为历史观测写日志，但不改变样本结果或恢复显示。多个窗口分别记录匿名 client ID，成功分母按样本计，同样本只算首次及时回报一次。

日志逐行记录会话开始、严格过滤后的源事件、拒绝原因、撤回屏障、浏览器 DOM/绘制机会/撤回回报、样本最终结果及结束报告。拒绝输入和拒绝回报单列计数；不能只保留成功事件。会话最多接受 1000 个机会、20000 次输入尝试和20000 个不同浏览器回报，达到限额停止显示，须重新开会话。日志写失败也停止显示。

| 报告字段 | 口径 |
| --- | --- |
| `opportunities` | 本服务实际接受的不同样本数；心跳/控制事件不增加，非法输入单列；不等于真实游戏全部机会 |
| `outcomes` | 包含等待中、及时绘制机会回报、结果超时、显示回报超时、无结果、未知，以及替代/撤回/断开等未回报原因 |
| `frame_to_emitted_ms` | 主机收帧到生产方签发，包含上游工作；没有把识别、判断分别测出来 |
| `emitted_to_ingested_ms` | 生产方签发到本服务读取，包括写文件和轮询等待；依赖输入同域声明 |
| `ready_ingested_to_report_received_ms` | 本服务收到 ready 到收到浏览器绘制机会回报，包含浏览器获取、调度和返回传输 |
| `frame_to_report_received_ms` | 主机收帧到服务端收到浏览器绘制机会回报；包含回程，不能命名为实际可见延迟 |
| `browser_dom_to_raf_ms` | 浏览器自己的 DOM 更新到第二次绘制回调时间，不与主机绝对时间相减 |
| `retired_reason / retired_at_monotonic_ns` | 提示之后何时、为何被服务端撤回；成功回报不抹掉撤回记录 |

P50/P95 只对有及时回报的样本计算，使用最近秩方法；同时返回完整机会分母、各失败结果和回报样本数。不把超时当成 0ms，也不把失败从报告中删除。首个样本和后续样本可从顺序及时间戳区分；本次没有做有统计意义的冷启动/预热分组实验。未测设备变化→收帧，未测人眼实际可见，也未验证原工程目标“收帧到可见中位数 ≤3 秒、P95 ≤5 秒”。
