# 18.6 公告局部策略比较 v1

`jcc_patch_strategy` 只把 `资料/版本数据/版本变动_18.6_第三方转述.json` 中明确的、自然之力模式专属数字变化应用到调用方明确为 `synthetic` 的测试算术。该账本来自 17173 的转载页面，页面标注来源为公众号；它不是完整英雄、羁绊、装备或配方目录，也没有绑定默认平板、实际对局或后续热修。

## 输入和边界

请求格式为 `jcc-patch-strategy-request/v1`，必须同时提供完整 18.6 账本、至少一个羁绊场景、至少一个装备场景，以及已被 `jcc_transition_coach` 接受的 synthetic 团队快照。账本必须仍声明：`fullCatalog=false`、`fullRecipeCatalog=false` 与 `decisionEligibility=false`。任何实时画面、回放、未知版本、缺失字段或未列入公告的数值都返回 `unknown`。

账本还必须逐字段匹配已发布的 18.6 账本的来源摘要和证据边界，并匹配其规范化 JSON 内容摘要；任一条目、版本、来源 URL、数值或边界被改写，均返回 `unknown`。规范化摘要只用于确认调用方没有替换本项目已审核的账本内容，**不认证** 17173 页面或其标称公众号来源，也不把第三方转载升级为官方或实机证据。羁绊计算只读取 `trait_balance` 分区；装备计算只读取 `item_balance_not_recipe_catalog` 分区；转型锚点同样只读取前者。因此同名同字段的装备与羁绊条目不能跨分区使用。

羁绊测试支持 `base_times_percent`：将调用方的虚构基数分别乘公告前后百分比，输出差额。单值无需额外选择；多值公告文本（当前为灵魂莲华 4 个值、约德尔人和朋友 3 个值）必须给出 `announced_value_ordinal`，即公告斜杠值的 **1 起始顺序号**。该号不是羁绊人数、激活阈值或阵容条件，模块不会猜测其映射。调用方还必须给出一个虚构备选贡献值，模块会报告公告属性与这个备选在该算术中的前后排序。这只是在给定属性、给定假设下的局部比较，不是棋子最终生命、战力或胜率。装备测试将调用方声明的虚构伤害量乘公告前后全能吸血百分比；可与调用方声明的虚构恢复量对照，用于验证数值变化可能改变一个**虚构**比较的排序。它不知道实际配方、携带者、伤害构成、治疗限制或装备强度。

英雄与强化入口同样严格按账本分区：`hero_balance` 的 16 条与 `augment_balance` 的 6 条当前都能解析为公告数字，但并不是完整机制模型。百分比字段只能用 `base_times_percent` 和调用方声明基数。英雄的 10 条非百分比斜杠数列必须同时给出 1 起始公告值序号、`declared_multiplier_base` 和 `same_unit_assumption=true`，只输出“公告裸数 × 调用方虚构乘数”的分量；不会把序号解释成星级或技能等级，也不会换算法术/物理单位。强化的两条裸数（基础抗性、初始金币）只支持 `announced_direct_value` 与 `same_unit_assumption=true` 的同单位直接差值。未列入账本、复合机制、触发条件、用途、单位换算及真实强度均为 `unknown`。

转型部分复用 `jcc_transition_coach` 的现有 synthetic 快照比较。它只验证被声明的羁绊门槛、人口、可见商店缺口等条件，不把虚构单位映射为 18.6 弈子，不输出真实阵容转型建议，也不评估即时战力。当前返回会明确 `patch_used_in_transition_score=false`：补丁字段可被读出作为来源上下文，但**尚未**进入该既有转型链的评分；切换转型锚点不应被误读为 18.6 改变了转型决策。

## 可复现实例

从仓库根目录运行：

```sh
PYTHONPATH=src python -m jcc_patch_strategy --demo
PYTHONPATH=src python -m unittest src/jcc_patch_strategy/tests/test_core.py -v
```

内置演示使用 `1000` 的虚构基数：永恒之森 9 阶生命值加成从 25% 变为 10%，对应的虚构百分比贡献从 250 降至 100，与 `175` 的虚构备选比较也会从公告属性较高变为备选较高。灵魂莲华按公告顺序 1–4 展示 `12→12`、`30→30`、`50→55`、`55→65`；约德尔人和朋友按顺序 1–3 展示 `15→15`、`28→30`、`33→38`，这些序号不表示任何实际阈值。正义之手的 `1000` 虚构伤害恢复从 150 降至 120。演示还逐条走过账本的 16 条英雄数值与 6 条强化数值入口，全部使用声明为 synthetic 的基数、乘数或同单位假设。演示中的备选恢复量、棋子、羁绊门槛、金币、商店和路线全部是 synthetic，不能迁移到真实对局。

## 输出

无论计算成功与否，`strategy_recommendation=false`、`execution_eligible=false` 且 `automatic_action=null`。成功只表示公告文字在虚构算术和既有 synthetic 合同中可重放；不表示当前版本、玩家局面、装备合成、阵容、羁绊身份、规则完整性或策略正确性已验证。
