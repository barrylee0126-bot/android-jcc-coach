# 25I：回放准备阶段线索的影子跟踪

状态：**离线开发实验**，不接平板、不生成正式局面、实时建议或动作。代码位于 [`jcc_prep_context`](../../src/jcc_prep_context/core.py)。它复用 `jcc_device.scene_evidence` 的局部 OCR、精确文字和回合语法，仅在已有录像逐帧输入上跟踪带条件的阶段候选。真人标注、独立人工复核和真实准确率均未知。

## 为什么需要保守输出

“商店可见”“回合号未变”“倒计时大于零”或“有空人口”都不证明正在己方准备阶段。用户的开发录像中，商店在战斗开始后仍可见；“准备阶段”横幅出现时，画面也可能处于暗场切换。界面上的圆形头像或调用方声明不能自动证明所看棋盘属于本人。

因此每个结果固定 `board_owner=unknown`、`visibility=unknown`、`advice_eligible=false`、`execution_eligible=false`。即使返回 `development_candidate/preparation`，也只表示配置区域中的 OCR 与外观跟踪满足实验条件；不证明本人棋盘、无遮挡、现在可操作、建议正确或实时可用。它不替代现有正式字段门控和 10E 的原始有效期。

## 输入与跟踪

`Layout` 显式接收图像精确尺寸、回合文字、购买经验、刷新、横幅和阶段标识区域，以及阶段标识的 RGB 平均绝对差阈值。没有默认真实设备坐标或阈值。相关布局、区域、缩放、阈值均由实验方选择；尺寸匹配不证明它们确实覆盖了场景、遮挡或玩家身份。每一帧由实验方传入图像、解码序号与视频 PTS；本模块不读取录像，也不会认证这些声明。不得给间隔抽样的图片重新编号并当作无缺口序列。

创建 `ShadowTracker(..., source_id=...)` 时必须声明一个非空来源标识，并在每次 `observe(..., source_id=...)` 与 `current(..., source_id=...)` 中重新提交相同标识。标识缺失、无效或改变会撤回已有候选；一旦声明来源改变，旧对象永久返回未知，须关闭旧跟踪器并为需要处理的来源创建新跟踪器，由画面重新建立锚点。切回原标识也不能恢复旧对象。该标识仅是调用方声明，本模块不认证它与图像或视频的真实关系；用同一个标识冒充不同来源仍可能无法发现。来源标识不出现在结果中，调用方应避免把私人来源信息写入公开日志。

`ShadowTracker.observe` 先对该图像重新调用现有 OCR 场景与回合探针；以下条件允许建立候选：同时出现回合、购买经验、刷新，以及明确的“准备阶段”横幅，回合文字具备合法语法。候选绑定当次输入图片的 SHA-256；该 SHA 属于私人数据，不应公开。横幅、区域、OCR 和回合均是机器线索，不是人工真值。

在原锚点的指定 PTS 有效期内，后续**逐个解码输入帧**仍须有同一回合候选、商店场景线索和与锚点相近的指定阶段标识；即使准备横幅仍在，每个已有锚点的帧也必须进行标识比较。该比较在 OCR 之前执行，避免阶段标识已变化但商店或横幅 OCR 暂时失败时漏掉冲突。这里的相似仅是对所选矩形计算 RGB 平均绝对差；它无法证明整个画面没有变化，必须按开发候选看待。续接不会延长锚点原期限。

一旦阶段标识差异超过阈值，当帧撤回为 `unknown/marker_changed` 并设置 `marker_conflict_locked=true`。此后该跟踪器一直锁存为未知：旧准备横幅持续、OCR 漏检或后来读到不同回合候选，都不会解除锁存；锁存期间不再执行场景 OCR，也不宣称检测到了后续阶段。由于本实验没有可认证的新回合依据，只有关闭旧对象、创建新跟踪器，并重新满足完整准备锚点条件，才可以产生新候选。此策略可能比必要的更保守，它不认证来源、本人棋盘、可见性或可操作性。

当 PTS 达到原锚点期限时，即使准备横幅仍在，当次调用也返回 `unknown/anchor_expired` 并清除锚点；调用方须立即清除旧结果。到期先于阶段标识比较，不把到期当作标识冲突。在随后的新帧，若完整场景与准备横幅线索仍被重新识别，可以建立一个新的锚点和新的期限。这样允许持续横幅跨期限重新建锚，但它不是同一个候选的无限续期：每次到期都先出现撤回，不保证横幅、本人归属或画面可操作。若通过 `current` 先检测到到期，下一次新帧同样须重新满足建锚条件。

明确的“战斗开始”文字立即撤回；它只作为撤回线索，不单独宣称游戏确在战斗中。回合变化、标识差异超限、缺少场景线索、阶段 OCR 错误/无法解析、无效图片、帧序号缺口、PTS 倒退或超出设置的帧间阈值、原锚点到期时均撤回。`current(pts_ns=...)` 由调用方使用同一录像 PTS 时钟主动调用，可在无新帧时发现静默或过期；`close()` 终止并撤回，不能重新启动同一对象。这个实验没有背景定时线程、墙钟或设备采集时钟。

输入序号与时间只是调用方声明，最多能检测声明序号缺口或 PTS 间隔超过阈值，不能证明录制端没有漏帧、时间准确、来源真实或抽帧不存在隐蔽缺口。`marker_max_mean_delta` 和时间阈值仅作开发对照，未校准为生产规则；把阈值调大不能证明行为安全。对象须由单一所有者串行调用；调用方不能缓存已撤回的结果。

## 实验解读

实际开发数据的一条局内连续段包含准备横幅、无横幅的准备外观、阶段标识变化及战斗横幅；另一段已有选秀画面可检查场景线索缺失。全部来自单局开发材料，布局和阈值在该材料上选择，不是盲测，也不是其他对局、模式、分辨率或用户设备的准确率。真实录像、带 PTS 和图片摘要的逐帧报告放在项目外的私有目录。

当前没有可认证的本人棋盘识别、对手棋盘识别、全屏遮挡检查或玩法规则绑定。若某帧先因标识冲突以外的原因撤回并清除了锚点，标识变化随后才出现，本实验不保留旧标识跨缺口比较；后续候选不足以证明缺口期间未发生冲突。未覆盖的局部弹窗、对手视角、伪造界面、被遗漏的细微切换、OCR 错字和与锚点相近但含义不同的阶段标识可能漏检；这些可能让阶段影子候选依旧存在。真实使用须先找到可验证的本人身份、可见性与上下文变化依据，再另行建立可追溯的回放及实机验证；不足时仍为未知。
