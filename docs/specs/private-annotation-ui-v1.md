# private-annotation-ui-v1：本机私有标注与复核界面

开发11F，2026-11-02；同日追加 100 张大图读取性能修复。入口为 [`src/jcc_annotation_ui`](../../src/jcc_annotation_ui/) 和可选启动器 [`tools/jcc-annotation-ui`](../../tools/jcc-annotation-ui)。本版提供中文样本列表、画面与区域查看、六个 M1 字段编辑和显式复核操作。

本交付仅用自生成图像验证软件，**没有读取真实候选图或清单，没有新增真实人工标注、真实人员独立复核或真实验收结果**。测试里声明 `sample_kind="real"` 的对象也只有生成像素与虚构元数据，用于测试契约边界。合成流程通过率不代表识别准确率。

## 1. 启动与使用

使用项目现有 `.venv`，没有新增依赖。在项目根目录运行：

```sh
# 先选一个尚不存在、未被同步的私有目录。不要填已有真实样本目录。
JCC_UI_DEMO_DIR="$HOME/Library/Application Support/jcc-annotation-ui-synthetic-v1"
tools/jcc-annotation-ui make-synthetic --private-dir "$JCC_UI_DEMO_DIR"
tools/jcc-annotation-ui serve --private-dir "$JCC_UI_DEMO_DIR" --sample-kind synthetic --open
```

第一条命令仅在新的目录生成两张明显标示为合成软件素材的 PNG，导入后所有标签未知、无复核、隔离区。`synthetic-import` 是合成导入步骤代号，不是人工姓名。创建命令拒绝覆盖已有目录。

打开已经准备好的真实工作区，须另外明确传入其绝对路径及 `--sample-kind real`。本界面不查找、推断、导入或转换真实来源。真实和合成工作区不能混用；实例在启动和每次读取、提交时都检查整个工作区类型。私有目录沿用 [sample-workflow-v1](sample-workflow-v1.md) 的仓库外、非同步目录、所有权、权限、链接和资产完整性要求。

没有启动器时，等效入口为：

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m src.jcc_annotation_ui serve \
  --private-dir "$JCC_UI_DEMO_DIR" --sample-kind synthetic --open
```

服务固定绑定 `127.0.0.1`，默认自动分配端口；可用 `--port` 指定端口，没有其他监听地址选项。未用 `--open` 时，终端会显示带一次实例会话凭据的专用链接，须在本机打开。凭据仅用于此实例，不应转发或放入报告。页面消费地址片段后立即将其从地址栏移除，凭据只留在页面内存；刷新需要重新启动实例。

使用顺序：

1. 选样本，检查画面、来源、图像校验和、当前修订和保存标签。列表可按样本或场次代号筛选。
2. 对六个字段逐个选择“是否适用也未知 / 适用但答案未知 / 已知 / 确实不适用”。已知答案须明确填写并设置该图证据区域；画框或四个归一化坐标输入均可。字段放大功能仅查看原始像素，不推断、不补全。
3. 遮挡时新增遮挡区域，将受影响字段保留未知，原因可选遮挡、不可读、动画、证据不足等。画面条件按需逐行填写。填入自己的非个人信息代号后，点击“保存标注”；保存会撤销旧复核。
4. 复核者重新查看当前保存图像、区域和全部标签，填写本人代号及私有依据代号，明确确认后提交。真实模式要求使用者声明是另一位实际人员；合成模式只能确认软件流程测试。未保存草稿不能提交复核。

有未保存草稿时切换样本会被阻止。可保存，或显式点击“丢弃草稿并重载”；本版不将草稿写入磁盘或浏览器存储，也不自动恢复/合并草稿。并发冲突后须重读、重新检查当前版本，不能直接重放旧复核。

列表先核对全库字节，所选图片在打开时完整核验内容；页面分别显示本次“字节已核对”与“图片内容已核验”的数量。可选的“完整核验图片”按钮会检查尚未解码的图片，保持草稿、修订、复核和分集不变；第一次可能较慢。未先点该按钮也可以明确保存，但提交前会完成同等的全库核验，不会跳过未查看图片。

“关闭服务”或终端 `Ctrl+C` 结束前台实例。离开/关闭页面时发送尽力而为的退出请求；浏览器未发送通知、崩溃或进程被终止时，认证心跳中断 90 秒后服务自动退出。没有安装常驻任务、登录项或后台守护进程。

## 2. 支持范围

| 内容 | 本版行为 |
| --- | --- |
| 场景、阶段 | 仅使用共享 Schema 的枚举，不由一个字段自动推出另一个字段 |
| 回合 | 明确的 `{stage, step}` 正整数 |
| 血量、金币 | 整数；不添加未经核实的模式上下限；空输入不能变为 0 |
| 等级 | 正整数；不代表棋子星级 |
| 适用、未知、遮挡、不适用 | 保持共享 `applicability/truth_status/value/reason/region` 关系；未知始终为空值 |
| 区域 | 整幅已解码图像左上角为原点的 `[0,1]` 正面积区域；显示字段名和已知/未知，并可放大原始像素 |
| 模式、版本、五格商店 | 显示完整保存标签，只读并按原值保留；没有默认空商店 |
| 来源、样本身份、组别、分集 | 只读；不提供导入、组别编辑、分集、删除、自动代表帧选择或导出入口 |

验收集的标注被冻结；需先通过原 SampleStore 工作流将整个关联场次移回隔离区，本界面不会代做分集。复核始终只记录当前保存标签，不修改答案。`adjudicated` 只表示使用者显式提交的裁定记录，未解决字段仍应保持未知。

代号不同只能满足契约中可机器检查的必要条件，**不能证明实际人员不同**。界面不做人员认证，不生成姓名、不自动提交真实复核、不判断来源真实性。真实人员安排、依据保存与来源核实由后续实际标注工作完成。

## 3. 与 SampleStore 的关系

`workspace.json` 仍是唯一持久真源；本模块不另存标签数据库、复核状态或映射文件，不修改共享 Schema、SampleStore 或其事件格式。

- `workspace.py` 与 `verified_store.py` 集中适配现有 Store。`VerifiedUIStore` 继承原锁、工作区封套、提交、事件和 Schema 校验；因为共享 Store 没有可替换的图像解码钩子，本模块本地镜像其 `_verify` 检查并加入可验证的解码派生结果复用。共享源码没有更改；未来共享校验变化时须同步审查本地镜像及回归用例。
- 初始化、列表、详情和读图都在原锁下重读当前 JSON、执行完整标注/跨记录 Schema 及资产映射检查，并重新打开所有资产，检查所有权、权限、硬链接、路径与大小限制，读取完整字节后计算 SHA-256。没有根据修改时间、大小、inode、修订号或上次成功记录断言文件未变。
- 库存/列表读取只证明当前 JSON 和资产字节与索引一致。首次尚未解码的图片不算“内容已核验”；即使损坏文件与伪造索引哈希一致，列表也不宣称全库内容有效。所选样本详情在返回前完整核验该图的格式、解码、尺寸、旋转与 RGBA 像素哈希；读图按同一视图绑定并再次读取实际响应字节、检查摘要。
- 已完整解码的派生信息只按**本次新读字节计算的 SHA-256**及当前解码政策命中；元数据中的期望哈希或文件 stat 不能代替本次计算。复用后仍逐项比较像素哈希、格式、尺寸、帧绑定与全库重复关系。内存最多 256 条派生信息，不保存原图、像素、标签或路径，不写磁盘；实例关闭清空，另一个实例不会共享。摘要变化、索引不匹配、解码限制变化或条目淘汰会拒绝请求或要求重新解码。
- 保存时只接受六个 M1 标签、普通条件和遮挡区域。其他标签从最新受验证记录原样复制；样本来源、类型、资产、帧、组别和分集不接受客户端更新。
- 只在显式保存时，创建随机 `edits/ui-<random>.json` 私有临时文件，调用原 `SampleStore.annotate()`，最后移除本次临时文件。该方法重新取锁、检查修订并通过原 Schema/跨记录校验后提交。外部进程恰在两次取锁之间写入时，旧修订仍被拒绝。
- 复核调用原 `SampleStore.review()`，保留原事件的标签哈希和依据代号。页面也显示该复核是否仍绑定当前标签；旧复核与当前标签不匹配时明确提示。
- 保存和复核的预检查及继承方法提交时均采用全库内容核验。默认写入校验不会继承列表的局部解码范围；每张资产必须由本次解码，或由本次完整字节摘要匹配的既有解码派生信息支持，并重新通过所有映射、几何、像素与跨记录限制。首次提交会解码尚未查看的全部图片；明确的只读完整核验可提前承担该成本。
- 页面视图带实例内存密钥签名，绑定完整当前记录、工作区修订、图像哈希及实例类型；图像请求、保存和复核都须匹配。新修订、另一张图、另一实例、标签/条件变动都会使旧视图不可提交。签名不证明人看过图片或标注正确。

正常失败、并发拒绝和模拟写入失败均保留旧真源，并清理本次临时编辑文件。强杀、断电或非合作进程直接修改私有文件仍受原工作流的事务和恢复边界约束；不要把残留临时材料视为接纳结果。

## 4. 遮挡约定与有效区域

为不改共享 Schema，界面将每个遮挡矩形编码为现有 `conditions` 中的一个约定字符串：

```text
jcc_ui:occlusion:[x_min,y_min,x_max,y_max]
```

坐标值是有限 JSON 数字；顺序固定，最多 32 个。普通条件编辑不能手工注入该保留前缀。该信息与标签一起经原 Store 校验、修订、原子保存和清单导出，不是第二份标签真源。其他消费者若不认识这个约定，仍须保留条件；共享校验器本身不解释遮挡含义。

本界面对共享契约增加保守的提交限制：六个 M1 已知答案必须有图中证据区域；任何已知标签（含已有只读标签）的非空证据区域与任一遮挡矩形存在正面积交叠时，保存和复核均拒绝。遮挡之间可以交叠，边缘接触不算正面积交叠。未知字段可保留区域及遮挡原因。未知区域不会自动升格为有效答案，遮挡标记也不会改写或脱敏原图。

若已有只读标签与遮挡冲突，须通过原工作流解决该字段，不能通过本界面偷偷覆写。区域由使用者判断；工具不能自动发现漏画的遮挡，也不能证明所框区域支持答案。放大画布限制在 600×360 像素以内，极窄区域不会产生无界画布。

## 5. 本机安全边界

- 仅一个显式私有目录、一个显式类型；没有任意路径、文件浏览、远程导入、上传或外链打开接口。图像只能按受验证样本 ID 读取经过索引绑定的 PNG/JPEG。
- Host 只接受精确的 `127.0.0.1:<port>`。Origin 如存在必须是本实例；写请求必须携带这个 Origin。拒绝跨站、其他端口同站请求、重复关键头、绝对地址及双斜杠请求目标。
- 所有样本 API（包括 GET 和图片）要求随机实例会话头；写操作还要求 JSON、明确长度及 128 KiB 以内正文，拒绝转移编码、内容编码、重复 JSON 键和非有限数字。无 CORS 放行或 cookie 凭据。
- 所有响应 `no-store`、`nosniff`、`no-referrer`、禁止嵌入；CSP 仅允许本机脚本、样式、连接和本机/内存图片，不允许内联脚本、表单、对象、worker 或外部资源。页面将所有样本及条件文本作为文本节点，不插入 HTML，不调用 `eval`。
- 不记录访问路径、标签、图片、用户输入代号、私有路径、异常详情或正文；不使用 localStorage、sessionStorage、服务工作线程或自动草稿文件。终端只输出必要启动/退出信息和不回显输入的错误码。

这是对跨站网页、误请求及不安全私有文件的防护。它不是对同一系统账号内可读私有目录的进程、浏览器扩展、系统截图或自定义同步/备份软件的隔离。图像与来源真实性、人员独立性仍不能由 HTTP 或 Schema 检查证明。

## 7. 100 张大图的读取性能与一致性

新增 [`benchmark_reads.py`](../../src/jcc_annotation_ui/tests/benchmark_reads.py) 只新建临时合成工作区，没有打开已有目录的参数。100 张 3200×2000 自生成纹理/文本 PNG 共 395,752,406 字节（377.42 MiB），标签全部未知，类型始终 synthetic。测试用批量构造仅装配全新的合成素材，不是产品导入或写入路径。原始测量见 [`scale-read-benchmark.json`](../../src/jcc_annotation_ui/evidence/scale-read-benchmark.json)。

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m src.jcc_annotation_ui.tests.benchmark_reads \
  --output src/jcc_annotation_ui/evidence/scale-read-benchmark.json
```

Python 3.11.16 / Pillow 13.0.0，同一自生成工作区、同一进程；没有清理操作系统文件缓存。“首次”指实例内没有已解码派生信息，不是物理磁盘冷读。旧基线使用修复前初始化/列表/详情所调用的完整 `SampleStore._load` 路径；各做一次。新列表做三次取中位，其余首次操作各一次；完整原始数组保留在 JSON。

| 操作 | 原全库解码路径 | 修复后 |
| --- | ---: | ---: |
| 初始化 | 7.345 秒 | 0.466 秒 |
| 未查看图片前的列表 | 7.362 秒 | 0.460 秒 |
| 首张详情 | 7.384 秒 | 0.539 秒 |
| 详情后的图像读取 | 7.433 秒 | 0.466 秒 |

首张详情只新增一次解码，图像请求不再重复解码。首次完整核验为 7.465 秒，完成余下 99 张解码；后续完整核验三次中位 0.458 秒。**没有先核验的另一个新实例首次保存仍需 8.469 秒**。已核验后保存 1.461 秒、复核 1.205 秒，均仍重新读文件、核对全库字节并经过原提交路径；这些是后端操作耗时，不是整个页面恢复时间。

同一规模的 Ego 浏览器实际操作见 [`scale-browser-checks.json`](../../src/jcc_annotation_ui/evidence/scale-browser-checks.json)、[截图](../../src/jcc_annotation_ui/evidence/05-scale-verification.png)：首次导航至可操作 1.764 秒、切换图片 2.268 秒、首次点击完整核验至恢复 8.197 秒、核验后点击保存至页面恢复 3.631 秒。上述单次观察包含浏览器、工具动作、网络传输和后续重载开销，不是置信区间或真实样本性能。完整核验期间保存/复核禁用，草稿保留且工作区字节未改；保存仍是另一次明确操作。保存/复核后不再额外请求一次整个列表，当前行由已重读的当前记录更新，其他行在显式重载时刷新。

一致性是原合作锁下的当前请求快照：每次重读 JSON 和资产字节，下一次请求再次核对；不是对返回后文件永不变化的承诺。非合作进程直接改文件仍受原工作流的同类时序边界约束。即便当前请求复用了派生信息，也不能据此绕开后续字节读取、权限检查、旧修订/视图拒绝或全库提交前核验。

剩余成本：每次读请求仍随全库压缩字节数及标注数线性增长；首次完整解码仍慢，未做后台服务、并行预取或磁盘缓存。256 条内存上限以外的工作区可能反复重新解码。本轮没有用真实画面调参，没有对总控先前测量的真实 100 张库执行复测或任何写入，不能把上述合成耗时当作真实库验收。
